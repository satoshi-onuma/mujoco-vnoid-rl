# RL実験管理アプリ 要件定義書

## 目的

本ドキュメントは，知能化生産システム論期末レポートで提案した「強化学習実験管理アプリ」に関する要件定義書です．

## 概要

### システム方式・構成

システム構成は次の通りです．

- Linux（Ubuntu）上で動作するローカルデスクトップアプリケーション（tkinter GUI）
- 研究で使用しているシミュレーション環境（vnoid＋MuJoCo，C++／Python）と同一マシン上で動作
- ※外部サーバは使用しない．（学習データ・評価結果はすべてローカルのファイルシステムとSQLiteに保存する．）

### 用語定義

- **強化学習（RL）**  
  モデルベースの2足歩行制御器に対して，方策学習によって歩行安定性を補正する介入を加える学習手法．本研究ではRay RLlibのPPOを使用．
- **報酬重み**  
  歩行軌道の追従性・関節動作の滑らかさ・姿勢の健全性など，複数の評価軸に対する重みパラメータ（`w_track` / `w_act` / `w_healthy` / `tracking_sigma`）．
- **地盤（terrain）**  
  歩行シミュレーションにおける路面の摩擦・接触パラメータの設定．エピソードは必ず硬地盤（`hard`）から始まり，歩行途中でC++側が決めたタイミングで指定した地盤（`soft` / `debug` / `random`）に切り替わる．
- **run（実験）**  
  1回分の学習実行単位．一意の `run_id` を持ち，設定・チェックポイント・ログ・評価結果が対応付けられる．
- **チェックポイント**  
  学習途中・終了時に保存される方策（ニューラルネットワークの重み）のスナップショット．評価（録画）時に読み込んで使用する．

## 業務要件

### 現状のフロー

アプリ導入前，研究における実験フローは次のようになっていました．

1. 報酬関数の重みをエディタ上で直接書き換える
2. ターミナルで学習スクリプトを起動．学習中は各エピソードの報酬内訳をログファイルに逐次書き出させておく
3. 学習完了後，とっておいたログから描画用スクリプトでグラフ化し，学習曲線を目視で確認
4. チェックポイントを指定してログ取得用スクリプトを手動実行
5. 実行しながら歩行距離など物理量をログに記録
6. ログを描画して物理量を確認
7. ログデータとグラフ，チェックポイントに判別可能なように名前を付けて保存
8. 次の重み配分を決定
9. 1へ戻る

学習中は進捗が見えず，完了してから初めて様子を確認するため，途中で異常を察知できない．また，実験ごとにログをとるために手作業でスクリプトを実行して待つので待ち時間が長く，可視化作業自体が手間になっていた．過去実験の設定・チェックポイント・評価結果の対応関係は手動整理と自分自身の記憶にしか存在せず，振り返りコストが高かった．

### 構築後のフロー

アプリ構築後，フローは次のようになります．

1. 実行タブのフォームに報酬重み・切替先地盤・PPOハイパーパラメータ・ひとことメモを入力し，「Run」ボタンで学習を起動する．コードを直接書き換える必要がなくなる
2. 学習は別プロセスとして起動され，進捗タブで学習曲線（Iteration毎の平均報酬）がリアルタイムに表示される．異常な学習を早期に察知できる
3. 学習が完了（または途中停止）すると，設定・チェックポイント・ログの場所が自動的にSQLiteデータベースへ記録される
4. 履歴タブで過去のrun一覧を確認し，気になるrunを選んで「評価を実行」を押すと，学習済み方策の録画・歩行距離の計測が実行される
5. 履歴タブから該当runの動画を再生して歩行の様子を確認できる．メモ欄で後から所感を書き足せる

### 利用者一覧

本研究を行う学生本人（開発者兼利用者）．研究室内で同テーマを引き継ぐ後任者も利用者として想定する．

### 規模

個人開発．実装工数はおおよそ以下の通り（実績ベース）．

- C++側バインディング拡張（報酬重み・地盤設定のPython連携）：小規模
- 学習・録画スクリプトのCLI引数化：中規模
- tkinter GUI（実行・進捗・履歴の3タブ）＋SQLite連携：中規模

## 機能要件

### 画面

- **実行タブ**  
  報酬重み・切替先地盤・PPOハイパーパラメータ・メモをフォームに入力し，学習を起動（Run）・停止（Stop）する画面
- **進捗タブ**  
  実行中の学習について，`training_stats.csv` を定期的に読み込み，matplotlibでIteration毎の平均報酬をグラフ表示する画面
- **履歴タブ**  
  過去の実験一覧をテーブル表示し，評価の実行・動画の再生・メモの編集を行う画面

### 権限

特になし（単一ユーザー利用のため認証・権限管理は行わない）．

### 帳票

本システムでは以下のファイルが出力されます．詳細は帳票仕様書を参照．

- 学習統計CSV（`training_stats.csv`）
- 学習ログ（`train.log`）
- 結果サマリJSON（`result.json`）
- チェックポイント（`checkpoint/`）
- 評価動画（`<terrain>_demo.mp4`）
- 評価ログ・制御ログCSV（`<terrain>_recording_log.csv` / `<terrain>_control_log.csv`）
- 評価実行ログ（`eval_<terrain>.log`）

### 情報・データ

本システムでは以下のデータが作成されます．

- 実験メタデータ・評価結果を保持するSQLiteデータベース（`experiments.db`，内部管理用）
- 学習・評価の成果物一式（外部出力，`~/vnoid-experiments/runs/<run_id>/` 配下）

### 外部インタフェース

- ファイルシステム：学習・評価スクリプト（`train_humanoid.py` / `record_humanoid.py`）とはCLI引数とファイル出力（CSV／JSON／チェックポイント）でやり取りする
- 動画再生：`xdg-open` を通じてOSの既定動画プレイヤーを起動する

### データフロー

本システムのデータ処理は次のようになります．

1. 実行タブのフォーム入力をパラメータ辞書に変換する
2. `subprocess.Popen` で `train_humanoid.py` を起動し，CLI引数として報酬重み・地盤・ハイパーパラメータを渡す
3. 学習プロセスは `~/vnoid-experiments/runs/<run_id>/` に `training_stats.csv`（進捗）・`checkpoint/`（方策）・`result.json`（最終結果）を書き出す
4. アプリは1秒間隔で `training_stats.csv` をポーリングして進捗タブのグラフを更新し，プロセス終了を検知するとSQLiteへ結果を記録する
5. 履歴タブから評価を実行すると，`subprocess.run` で `record_humanoid.py` を起動し，チェックポイントを読み込んで動画・歩行距離を計算する
6. 評価結果（歩行距離・動画パス・ログパス）はSQLiteの `evaluations` テーブルに記録される

## 非機能要件

### 互換性

Linux（Ubuntu，micromamba環境 `robot_env`，Python 3.10）を対象とする．C++拡張モジュール（`vnoid_rl_env`）はCMakeでビルドしたものを使用する．

### 処理時間

- 学習：ハイパーパラメータ（並列環境数・Iteration数）に依存し，1runあたり数分〜数十分
- 評価（録画）：1地盤あたり1エピソード分（数十秒〜1分程度）を目安とする

### データの保存場所

生成物はすべてリポジトリ外の `~/vnoid-experiments/` に保存する．

```
~/vnoid-experiments/
  archive/          # 過去実験の退避先
  runs/
    experiments.db  # SQLite
    <run_id>/
      checkpoint/
      training_stats.csv
      result.json
      train.log
      <terrain>_demo.mp4
      <terrain>_recording_log.csv
      <terrain>_control_log.csv
      eval_<terrain>.log
```

## 現状の実装スコープと今後の課題

期末レポートの提案（WebUI，並列探索モジュール，学習完了後の自動評価，学習曲線比較）に対し，実装は次のようにスコープを縮小している．

| レポート提案 | 実装 |
|---|---|
| WebUI | tkinterデスクトップアプリ |
| 単発実験モード＋範囲指定の並列探索モード（Ray） | 単発実験モードのみ |
| 学習完了時に自動で複数地形評価 | 履歴タブから手動で評価を実行 |
| 過去実験の学習曲線比較機能 | 一覧表示と個別の動画再生のみ |

今後，並列探索・自動評価・学習曲線比較を段階的に追加していくことを課題とする．
