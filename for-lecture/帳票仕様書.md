# 帳票仕様書

本仕様書は，RL実験管理アプリ（`rl_experiment_app`）に対する帳票仕様書である．
出力はすべて `~/vnoid-experiments/runs/<run_id>/` 配下に生成される．

## １．帳票一覧書

| ID | 帳票名 | 出力するファイル名，形式 | 概要 |
|---|---|---|---|
| 1 | 学習統計CSV | `training_stats.csv`<br>形式は `.csv` のみ | 学習の各Iterationにおける平均報酬・平均エピソード長・所要時間を記録したファイル。進捗タブがこれを定期読込してグラフ表示する |
| 2 | 学習ログ | `train.log`<br>形式は `.log`（テキスト） | 学習プロセス（`train_humanoid.py`）の標準出力・標準エラー出力をそのまま書き出したファイル |
| 3 | 結果サマリJSON | `result.json`<br>形式は `.json` | 学習終了時に出力される，最終報酬・最終エピソード長・所要時間・設定値一式をまとめたファイル。アプリはこれを読んでDBに反映する |
| 4 | チェックポイント | `checkpoint/` 配下（Ray RLlib形式のディレクトリ一式） | 学習済み方策（ニューラルネットワークの重み）のスナップショット。10 Iterationごとと学習終了時に保存され，評価時に読み込まれる |
| 5 | 評価動画 | `<terrain>_demo.mp4`<br>形式は `.mp4` のみ | 指定した切替先地盤（`soft` / `random` など）での評価実行時に録画される歩行動画 |
| 6 | 評価用制御ログ | `<terrain>_control_log.csv`<br>形式は `.csv` のみ | 評価実行中のロボットの姿勢・関節角度・ZMP等の物理量を記録したC++側のログ。歩行距離の算出に使用する |
| 7 | 評価用フレームログ | `<terrain>_recording_log.csv`<br>形式は `.csv` のみ | 評価実行中の各ステップの報酬・観測値（obs）を記録したPython側のログ |
| 8 | 評価実行ログ | `eval_<terrain>.log`<br>形式は `.log`（テキスト） | 評価プロセス（`record_humanoid.py`）の標準出力・標準エラー出力をそのまま書き出したファイル |
| 9 | 実験データベース | `experiments.db`<br>形式は `.db`（SQLite） | 全runの設定・状態・評価結果を集約管理するデータベース（内部管理用，帳票としては直接参照しない） |

## ２．帳票詳細書

### 学習統計CSV（`training_stats.csv`）

ヘッダー行と，Iterationごとの1行から構成されるCSVファイル．

| 列名 | 内容 |
|---|---|
| `iteration` | Iteration番号（0始まり） |
| `reward_mean` | そのIterationにおける平均報酬（`episode_return_mean`） |
| `episode_len_mean` | 平均エピソード長 |
| `sample_time_s` | サンプル収集にかかった時間（秒） |
| `learn_time_s` | 学習（勾配更新）にかかった時間（秒） |
| `elapsed_time_s` | 学習開始からの累計経過時間（秒） |
| `iter_time_s` | そのIteration全体にかかった時間（秒） |

各Iteration完了ごとに1行追記し，即座に `flush` される（学習途中でも進捗タブから最新状態を読み取れるようにするため）．

### 結果サマリJSON（`result.json`）

学習終了時に一度だけ出力されるJSONファイル．主なキーは次の通り．

```json
{
  "run_id": "20260726_212758_d2a819",
  "run_dir": "/home/satoshi/vnoid-experiments/runs/20260726_212758_d2a819",
  "checkpoint_dir": ".../checkpoint",
  "csv_path": ".../training_stats.csv",
  "final_reward_mean": 12.3,
  "final_episode_len_mean": 45.2,
  "elapsed_time_s": 1234.5,
  "num_iterations": 100,
  "reward_weights": {"w_track": 1.0, "w_act": 0.1, "w_healthy": 1.0, "tracking_sigma": 0.02},
  "terrain_mode": "soft",
  "hyperparams": {"lr": 0.0001, "gamma": 0.99, "num_workers": 8, "num_gpus": 1, "seed": 42}
}
```

アプリの `TrainingLauncher._finalize()` がこのファイルを読み込み，`experiments` テーブルの `status` を `completed` に更新し，最終報酬・エピソード長・経過時間・チェックポイントパスを反映する．ファイルが存在しない場合は `status` を `failed` として記録する．

### チェックポイント（`checkpoint/`）

Ray RLlib（PPO）標準の保存形式に従うディレクトリ．方策の重みは以下のパスに格納される．

```
checkpoint/
  learner_group/
    learner/
      rl_module/
        default_policy/   ← 評価時に RLModule.from_checkpoint() で読み込むパス
```

10 Iterationごと（`(i + 1) % 10 == 0`）と学習終了時に上書き保存される．

### 評価動画（`<terrain>_demo.mp4`）

- ファイル名は評価対象の切替先地盤名を接頭辞として付与する（例：`soft_demo.mp4` / `random_demo.mp4`）
- 解像度 1280×720，出力FPSはデフォルト30fps（`--output-fps` で変更可）
- 1エピソード分（転倒または規定ステップ到達まで）のフレームを `imageio.mimsave` でエンコードする

### 評価用制御ログ（`<terrain>_control_log.csv`）

C++側（`VnoidEnv`）が録画対象エピソードの最初の1エピソード分のみ記録するログ．基準座標・重心位置・ZMP・関節角度など多数の物理量列を持つ．評価スクリプトはこのCSVの `base_pos_x` / `base_pos_y` の始点・終点から歩行距離（ユークリッド距離）を算出する．

### 評価用フレームログ（`<terrain>_recording_log.csv`）

Python側（`record_humanoid.py`）が各ステップごとに記録するログ．

| 列名 | 内容 |
|---|---|
| `step` | ステップ番号 |
| `reward` | そのステップの報酬 |
| `terminated` / `truncated` | エピソード終了フラグ |
| `obs_0` ～ `obs_18` | 観測ベクトルの各要素 |

### 評価実行ログ（`eval_<terrain>.log`）

`record_humanoid.py` の標準出力・標準エラーをまとめて書き出したテキストファイル．末尾付近に評価結果を機械可読な1行JSONとして出力する `EVAL_RESULT_JSON:{...}` 行が含まれ，`EvalLauncher` がこれをパースしてDBの `evaluations` テーブルへ記録する．主なキーは `terrain_mode` / `walk_distance` / `video_path` / `log_csv_path` / `checkpoint_dir` / `num_frames`．
